# 목표 실행 파트너 서비스 제품 기획서

- 작성일: 2026-08-12
- 문서 상태: 문제·제품 가설 초안
- 개발 환경: 앱인토스 미니앱
- 임시 서비스명: `페이스메이트`
- 첫 상품: `7일 공부짝`

## 1. 제품 정의

### 한 문장 정의

> 이루고 싶은 목표와 실행 가능한 시간을 입력하면, 나와 실행 궁합이 맞는 한 사람을 연결해 함께 지속하게 해주는 목표 파트너 서비스.

### 첫 상품의 약속

> 혼자서는 미루게 되는 공부를, 나와 실행 리듬이 맞는 한 사람과 7일 동안 실제로 이어간다.

### 장기 비전

공부를 시작으로 자격증, 이직 준비, 사이드 프로젝트, 영어, 독서, 운동처럼 `혼자서는 미루기 쉬운 반복 목표`를 함께 실행할 파트너를 연결한다.

### 제품의 경계

이 서비스는 다음이 아니다.

- 사용자가 수많은 모임을 둘러보는 소모임 게시판
- 프로필과 외모를 탐색하는 친구·연애 매칭
- 지식을 가르쳐주는 과외·멘토링
- 여러 사람이 대화하는 관심사 커뮤니티
- 프로젝트 직군을 모아주는 팀 빌딩 서비스

제품의 본체는 `탐색`이 아니라 `실행 궁합 매칭 → 약속 → 실제 참여 → 반복`이다.

## 2. 해결하려는 문제

### 사용자 관찰

- 사람들은 공부해야 한다고 생각하지만 일과 후 혼자 시작하기 어렵다.
- 기존 스터디 모집 서비스에는 참여할 수 있는 방과 모집 글이 많지만 자신에게 맞는 모임을 직접 찾아야 한다.
- 모집 당시의 의욕과 실제 참여율 사이에 차이가 크다.
- 단체 스터디는 한두 명이 빠지기 시작하면 책임감이 빠르게 약해진다.
- 장기 스터디는 시작 부담이 크고, 일회성 집중방은 관계와 지속성이 약하다.
- 사용자가 원하는 것은 새로운 사람을 아는 것보다 예정한 공부를 실제로 끝내는 것이다.

### 핵심 문제

> 혼자 공부하면 미루게 되는 사람은 함께할 사람을 찾을 수는 있지만, 자신과 시간·강도·실행 방식이 맞고 실제로 약속을 지킬 사람을 찾기 어렵다.

### 해결 가설

사용자가 직접 방과 사람을 탐색하지 않아도 목표와 실행 조건을 입력하면 한 명을 추천하고, 두 사람의 7일 약속과 매일의 시작·완료를 관리하면 혼자 공부할 때보다 실제 실행 횟수가 증가한다.

## 3. 목표 사용자

### 1차 핵심 사용자

`공부·자기계발 목표가 이미 있지만 혼자서는 주 2회 이상 미루며, 기존 단체 스터디의 낮은 참여율에 실망한 경험이 있는 성인`

직업이나 공부 분야로 사용자를 제한하지 않는다. 첫 사용자 범위는 `반복할 공부 목표가 있는가`, `함께 실행할 고정 시간이 있는가`, `혼자 할 때 실제로 미루는가`라는 행동으로 정의한다.

#### 행동 특성

- 공부할 주제, 강의 또는 시험이 이미 정해져 있다.
- 지식 부족보다 시작과 지속이 어렵다.
- 평일 저녁 또는 주말에 반복 가능한 시간이 있다.
- 누군가 같은 시간에 기다리고 있으면 참여할 가능성이 높아진다.
- 대형 커뮤니티보다 부담 없는 1대1 관계를 선호한다.
- 연애나 인맥이 아니라 공부 실행이 목적이다.

### 첫 상품에 포함하는 공부 목표

- 직무 역량과 실무 공부
- 자격증·시험·취업 준비
- 외국어·독서·글쓰기
- 강의·책·문제집 완주

### 후속 확장 사용자

- 사이드 프로젝트를 혼자 진행하는 사람
- 반복적인 운동·생활 습관을 만들고 싶은 사용자

### 초기 제외 사용자

- 지식을 설명해줄 멘토를 찾는 사용자
- 여러 명과 토론하는 전통적 스터디를 원하는 사용자
- 프로젝트 팀원을 채용하려는 사용자
- 이성 교제나 오프라인 친목이 주목적인 사용자
- 미성년자

## 4. 사용자의 해야 할 일(JTBD)

### 기능적 과업

> 내가 정한 시간에 공부를 시작하고, 이번 주 목표만큼 실제로 공부하고 싶다.

### 감정적 과업

> 또 미뤘다는 자책 대신 누군가와 약속을 지켰다는 성취감을 느끼고 싶다.

### 사회적 과업

> 의욕만 앞서는 사람이 아니라 꾸준히 배우고 성장하는 사람이 되고 싶다.

## 5. 핵심 가치와 차별점

### 기존 경험

```text
모임 검색
→ 모집 글 비교
→ 지원·승인 대기
→ 단체 채팅방 입장
→ 일정 조율
→ 참여 저하
```

### 제안하는 경험

```text
목표와 실행 조건 입력
→ 가장 잘 맞는 한 사람 추천
→ 7일 약속 자동 생성
→ 함께 시작·완료
→ 연장 또는 재매칭
```

### 핵심 메시지

> 사람을 찾지 마세요. 이번 주 목표를 입력하세요.

### 핵심 차별점

1. 모임과 프로필을 무한 탐색하지 않는다.
2. 같은 공부 분야보다 실제로 함께할 수 있는 시간과 실행 강도를 우선한다.
3. 첫 관계를 7일로 제한해 시작 부담을 낮춘다.
4. 매칭 이후의 실제 참여를 제품이 관리한다.
5. 누적된 참여 기록으로 약속을 지키는 사람끼리 연결한다.

## 6. 핵심 개념: 실행 궁합

`방향성이 맞는다`는 것은 같은 기술을 공부한다는 의미만이 아니다. 다음 조건을 함께 본다.

- 목표 유형: 실무 역량, 이직, 자격증, 사이드 프로젝트, 습관
- 실행 시간: 가능한 요일과 시작 시각
- 실행 강도: 주당 횟수와 한 번의 집중 시간
- 진행 방식: 각자 집중, 결과 공유, 질문·토론
- 상호작용 방식: 상태만 공유, 텍스트, 음성, 카메라
- 책임감 강도: 가벼운 응원, 매일 확인, 강한 독려
- 참여 신뢰도: 약속한 세션의 실제 완료 비율

같은 기술 분야는 좋은 대화와 공감에 도움이 되지만 필수 조건으로 두지 않는다. 초기 사용자 수가 적을 때는 `시간·실행 방식·참여 신뢰도`를 우선한다.

## 7. 첫 상품: 7일 공부짝

### 상품 단위

- 기간: 7일
- 권장 약속: 주 3~5회
- 기본 세션: 60분
- 관계: 1대1
- 목적: 각자의 공부 목표 실행
- 종료: 함께 연장 또는 새로운 파트너 요청

### 첫 출시 범위

직업이나 공부 분야는 제한하지 않되, 초기 매칭 밀도를 위해 참여 조건을 다음과 같이 모은다.

- 대상: 만 19세 이상 성인
- 방식: 전국 온라인
- 목표: 반복 실행할 수 있는 모든 공부·자기계발
- 시간: 초기에는 평일 밤 9시·10시 등 수요가 많은 시간대에 집중
- 관계: 한 번에 한 명의 공부짝
- 기간: 7일

예를 들어 개발 공부, 영어, 자격증을 준비하는 세 사람이 모두 같은 시간대의 공부 파트너 후보가 될 수 있다. 공부 분야 일치는 가산점으로만 사용하고 매칭의 필수 조건으로 두지 않는다.

### 기본 세션 형식

```text
시작 5분   오늘 할 일 한 줄 공유
집중 50분  각자 공부, 상대의 참여 상태만 확인
종료 5분   결과 한 줄과 완료 상태 공유
```

카메라와 음성은 초기 필수 조건으로 두지 않는다. 두 사람이 같은 방식에 동의했을 때만 사용한다.

## 8. 핵심 사용자 흐름

### 8.1 온보딩

1. 사용자가 이번 주 공부 목표를 입력한다.
2. 공부 분야와 구체적인 목표를 고른다.
3. 가능한 요일·시간을 여러 개 선택한다.
4. 주당 원하는 횟수와 세션 길이를 선택한다.
5. 공부 방식과 소통 방식을 선택한다.
6. 원하는 독려 강도를 선택한다.
7. 매칭 요청을 보낸다.

입력 예시:

```text
이번 주 목표
SQLD 문제집 5개 단원 완주

가능 시간
월·화·목 22:00~23:00

공부 방식
각자 집중하고 끝에 결과 공유

소통 방식
텍스트만 사용
```

### 8.2 매칭 제안

1. 시스템이 가장 실행 궁합이 높은 한 사람을 제안한다.
2. 사용자는 상대의 최소 정보와 궁합 근거를 확인한다.
3. 두 사람이 제한 시간 안에 수락하면 매칭된다.
4. 한쪽이 거절하거나 응답하지 않으면 다음 후보를 찾는다.

매칭 카드 예시:

```text
이번 주 공부짝을 찾았어요

직장인 · 자격증 준비
정보처리기사 실기 공부 중

가능 시간 일치       100%
공부 방식 일치       각자 집중형
최근 약속 참여율     92%

왜 잘 맞나요?
월·화·목 밤 10시에 함께 공부할 수 있어요.
```

프로필 사진, 회사명, 상세 경력은 매칭 판단의 중심에 두지 않는다.

### 8.3 7일 약속 확정

1. 공통으로 가능한 세션이 자동 제안된다.
2. 두 사람이 이번 주 최소 참여 횟수를 확인한다.
3. 취소 가능 시간과 노쇼 기준에 동의한다.
4. 첫 세션 일정이 생성된다.

### 8.4 매일 공부

1. 세션 10분 전에 알림을 받는다.
2. `오늘 참여해요`를 눌러 참석 의사를 확인한다.
3. 시작 시 오늘의 목표를 한 줄 입력한다.
4. 두 사람의 `공부 중` 상태와 남은 시간을 확인한다.
5. 종료 시 완료 여부와 결과를 한 줄 남긴다.
6. 서로에게 간단한 응원 반응을 보낸다.

### 8.5 7일 종료

1. 함께 완료한 횟수와 개인 참여율을 확인한다.
2. 상대가 공부 실행에 도움이 되었는지 평가한다.
3. 두 사람 모두 원하면 한 주 연장한다.
4. 한쪽이라도 원하지 않으면 관계를 종료하고 새 매칭을 선택한다.

## 9. 매칭 원칙

### 필수 조건

- 최소 3개의 공통 가능한 세션
- 동일한 언어
- 호환되는 소통 방식
- 주당 참여 횟수 차이가 1회 이하
- 서로 차단·신고 이력이 없음

### 초기 매칭 점수 가설

| 항목 | 비중 | 이유 |
|---|---:|---|
| 공통 가능 시간 | 35% | 실제로 함께 참여할 수 있어야 함 |
| 실행 강도 | 20% | 원하는 빈도와 세션 길이가 맞아야 함 |
| 공부·소통 방식 | 20% | 카메라·음성 부담과 상호작용 기대 차이를 줄임 |
| 목표·관심 분야 | 15% | 공감과 대화 소재를 높임 |
| 참여 신뢰도 | 10% | 반복 이용 시 노쇼 가능성을 낮춤 |

운영 데이터가 쌓이면 완료율과 연장률을 기준으로 비중을 조정한다.

### 신규 사용자 처리

신규 사용자는 참여 이력이 없으므로 불리하게 평가하지 않는다. 첫 주는 `신규`로 표시하고, 약속 완료 후 참여 기록을 만든다.

### 사용자 선택권

- 한 번에 한 명만 추천한다.
- 추천을 수락하거나 한 번 재매칭을 요청할 수 있다.
- 무한 프로필 탐색은 제공하지 않는다.
- 매칭이 성사된 뒤 언제든 신고·차단할 수 있다.

## 10. 참여 신뢰와 노쇼 정책

### 참여 상태

- 완료: 시작·종료 확인을 마침
- 지각: 시작 후 10분 이내 참여
- 사전 취소: 시작 2시간 전까지 취소
- 당일 취소: 시작 2시간 이내 취소
- 노쇼: 사전 취소 없이 참여하지 않음

### 초기 정책

- 사전 취소는 참여율에 불이익을 주지 않는다.
- 당일 취소와 노쇼는 구분해 기록한다.
- 첫 노쇼에는 사유 확인과 정책 안내를 제공한다.
- 반복 노쇼 사용자는 일정 기간 신규 매칭을 제한한다.
- 파트너가 첫 세션부터 노쇼하면 피해 사용자에게 즉시 재매칭을 제공한다.
- 공개적인 별점보다 `최근 약속 참여율`만 보여준다.

금전 예치와 벌금은 효과보다 결제·분쟁 부담이 크므로 MVP에서 제외한다.

## 11. 화면 구조

### 하단 메뉴 가설

1. `오늘`: 다음 세션과 오늘 목표
2. `공부짝`: 파트너, 공통 일정, 이번 주 진행률
3. `기록`: 공부 시간, 완료 세션, 연속 참여
4. `내 목표`: 목표와 매칭 조건 관리

### 첫 화면 예시

```text
오늘 22:00 · 공부짝과 세 번째 약속

SQLD 문제집 1개 단원 풀기
시작까지 38분

[오늘 참여해요]

이번 주 함께 2/4회 완료
나의 참여율 100%
```

## 12. 알림 정책

- 매칭 제안 도착
- 매칭 수락 제한 시간 1시간 전
- 첫 주 일정 확정
- 세션 1시간 전 일정 변경 마감 안내
- 세션 10분 전 시작 안내
- 상대가 먼저 입장했을 때
- 종료 기록 미작성 안내
- 7일 종료와 연장 선택

파트너의 행동을 이용해 불안이나 죄책감을 과도하게 자극하는 문구는 사용하지 않는다.

## 13. MVP 범위

### 반드시 포함

- 공부 목표 입력
- 가능한 요일·시간과 실행 방식 설정
- 1대1 매칭 제안·수락·재매칭
- 7일 공통 일정 생성
- 세션 시작·종료 확인
- 동시 집중 타이머와 상대 참여 상태
- 목표·결과 한 줄 공유
- 주간 완료 횟수와 참여율
- 연장·종료·재매칭
- 신고·차단
- 최소 운영자 관리 화면

### MVP에서 제외

- 프로필 스와이프와 검색
- 공개 모집 게시판
- 자유로운 단체 채팅방
- 영상통화 직접 구현
- 멘토링과 지식 평가
- 다인 스터디
- 팀원 모집과 프로젝트 관리
- 오프라인 만남
- 금전 벌금과 보상
- AI 학습 콘텐츠 추천
- 공부 외 목표 카테고리

### 구현 전제

초기 매칭은 완전 자동화할 필요가 없다. 신청 조건을 받아 운영자가 후보를 확인하는 반자동 방식으로 시작해도 사용자 경험은 동일하게 검증할 수 있다.

## 14. 핵심 지표

### 북극성 지표

`주간 페어 완료 세션 수`

두 사람이 모두 시작하고 종료한 공부 세션의 수로 정의한다.

### 퍼널 지표

- 온보딩 완료율
- 매칭 요청률
- 매칭 제안 수락률
- 매칭 후 첫 세션 완료율
- 약속된 세션의 페어 완료율
- 7일 종료 후 같은 파트너 연장률
- 종료 후 새 파트너 재매칭률

### 공급·품질 지표

- 매칭까지 걸린 시간
- 공통 시간이 없어 매칭되지 않은 비율
- 당일 취소율과 노쇼율
- 신고·차단률
- 매칭 종료 사유

방문 횟수와 체류 시간은 주요 성공 지표로 사용하지 않는다. 사용자가 실제로 공부했는지가 더 중요하다.

## 15. 개발 전 수동 검증

### 7일 컨시어지 실험

- 참가자: 혼자 공부를 미루는 성인 20명
- 방식: 설문으로 조건을 받고 운영자가 10쌍을 직접 매칭
- 기간: 7일
- 약속: 주 4회, 회당 60분 권장
- 도구: 기존 화상회의·메신저와 간단한 시작·종료 기록
- 조사: 시작 전 인터뷰, 매일 완료 기록, 종료 인터뷰

### 확인할 질문

1. 파트너가 있다는 사실로 혼자일 때보다 공부 횟수가 늘었는가?
2. 같은 공부 주제와 같은 실행 시간 중 무엇이 더 중요했는가?
3. 카메라·음성 없이도 상대의 존재가 충분히 느껴졌는가?
4. 한 줄 목표·결과 공유가 동기를 높였는가, 부담을 만들었는가?
5. 같은 사람과 연장하고 싶은 이유와 바꾸고 싶은 이유는 무엇인가?
6. 무료가 아니어도 계속 사용할 의향이 있는가?

### 초기 통과 기준

- 참가자의 60% 이상이 약속한 세션 중 75% 이상 완료
- 전체 약속 세션의 페어 완료율 60% 이상
- 참가자의 40% 이상이 같은 파트너와 한 주 연장 희망
- 참가자의 30% 이상이 유료 사용 의향 표시
- `혼자였다면 하지 않았을 공부를 했다`는 경험이 반복적으로 확인됨

## 16. 분야 확장 원칙

### 변하지 않는 공통 엔진

```text
목표 설정
→ 실행 궁합 매칭
→ 기간 약속
→ 반복 실행·인증
→ 신뢰 기록
→ 연장·재매칭
```

### 확장 순서 가설

1. 학습 목표: 직무 역량, 자격증, 외국어, 독서
2. 결과물 목표: 취업 준비, 포트폴리오, 사이드 프로젝트, 글쓰기
3. 건강 목표: 운동과 식습관
4. 생활 목표: 기상, 정리, 기록 등 반복 습관

새 분야는 기존 사용자가 실제로 요청하고, 같은 실행 구조로 완료 여부를 정의할 수 있을 때만 추가한다.

### 당분간 확장하지 않는 분야

- 동네 친구·식사·여행
- 연애·소개팅
- 단발성 오프라인 모임
- 전문 지식이 필요한 코칭·상담

이 분야들은 반복 실행보다 호감, 안전, 장소, 전문성 문제가 더 중요해 별도 제품이 될 가능성이 높다.

## 17. 수익화 가설

MVP에서는 결제보다 실행 효과를 먼저 검증한다.

후속 가설은 다음과 같다.

- 무료: 동시에 한 개의 7일 목표와 기본 매칭
- 유료: 빠른 재매칭, 세밀한 조건 설정, 복수 목표, 장기 기록
- 조직용: 부트캠프·기업 교육 참여자의 실행 파트너 운영

사용자가 돈을 내는 이유는 사람의 프로필을 더 많이 보기 위해서가 아니라, 목표를 더 높은 확률로 완주하기 위해서여야 한다.

## 18. 주요 위험

| 위험 | 영향 | 초기 대응 |
|---|---|---|
| 초기 사용자 부족 | 원하는 시간에 매칭 불가 | 첫 모집 시간을 평일 22시 등으로 집중 |
| 노쇼 | 상대의 신뢰와 재사용 의향 하락 | 사전 참석 확인, 즉시 재매칭, 반복 노쇼 제한 |
| 기대 방식 불일치 | 공부보다 대화·친목에 치우침 | 상호작용 방식을 매칭 전에 명시 |
| 연애·영업 목적 유입 | 안전과 서비스 정체성 훼손 | 최소 프로필, 연락처 비공개, 신고·차단 |
| 인증 조작 | 참여 기록 신뢰 저하 | 완벽한 감시보다 두 사람의 동시 시작·종료를 기준으로 사용 |
| 관계 피로 | 매일 상대를 챙기는 일이 부담 | 응원 문구와 체크인을 짧고 구조화 |
| 분야 조기 확장 | 사용자 밀도와 메시지 분산 | 공부 목표에서 페어 완료율을 먼저 검증 |

## 19. 현재 결정과 가설

### 현재 결정

- 장기적으로 목표 실행 분야를 확장한다.
- 첫 상품은 직업과 무관한 공부 목표로 제한한다.
- 방 탐색보다 자동 매칭을 중심으로 한다.
- 일회성이 아닌 7일 파트너를 기본 상품으로 한다.
- 같은 목표보다 실행 시간과 방식의 궁합을 우선한다.
- 매칭 이후의 실제 완료를 핵심 가치로 둔다.

### 검증이 필요한 가설

- 7일이 관계 부담과 지속성 사이의 적절한 기간인가?
- 1대1이 소규모 그룹보다 책임감을 높이는가?
- 카메라·음성 없이도 상대의 존재가 동기가 되는가?
- 사용자는 자동 추천된 한 명을 신뢰하고 수락하는가?
- 참여율 공개가 신뢰를 높이는가, 감시받는 느낌을 만드는가?
- 공부 분야가 달라도 실행 리듬이 맞으면 만족하는가?
- 앱인토스 이용자가 낯선 사람과 공부짝을 맺는 데 충분한 신뢰를 느끼는가?

## 20. 다음 기획 결정

다음 순서로 결정한다.

1. 기본 세션에서 상대의 존재를 어떻게 느끼게 할 것인가?
2. 텍스트·음성·카메라 중 어디까지 MVP에 포함할 것인가?
3. 7일 동안 고정 일정을 약속할지 매일 가능한 시간을 조정할지 결정한다.
4. 매칭 전 사용자에게 보여줄 최소 프로필 정보를 정한다.
5. 첫 20명을 어디에서 어떻게 모집할지 정한다.
6. 수동 검증에서 사용할 실제 운영 규칙과 안내문을 만든다.
